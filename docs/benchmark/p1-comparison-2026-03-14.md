# P1 高并发对比压测报告（2026-03-14）

## 1. 测试目标

验证 P1 阶段“网关限流 + 异步落单 + 幂等补偿”在高并发下的效果，重点关注：

- 吞吐（RPS）
- 延迟分位（P95/P99）
- 成功率与失败类型
- 库存一致性（是否超卖）
- 异步最终一致性（是否最终全部落单）

## 2. 测试环境与参数

- 入口地址：
  - 场景 A（经网关）：`http://localhost:8080`
  - 场景 B（直连服务）：`http://localhost:8005`
- 脚本：`scripts/loadtest/p0-seckill-benchmark.mjs`（已增强非 JSON 响应容错）
- 并发参数：
  - `TOTAL=3000`
  - `CONCURRENCY=300`
  - `STOCK=1000`
  - `PRODUCT_ID=3`

## 3. 压测结果（P1）

| 指标 | 场景 A：经网关(8080) | 场景 B：直连秒杀服务(8005) |
|---|---:|---:|
| 总请求数 | 3000 | 3000 |
| 成功数 | 537 | 1000 |
| 失败数 | 2463 | 2000 |
| 成功率 | 17.90% | 33.33% |
| RPS | 2710.25 | 2412.49 |
| 平均时延 | 99.46 ms | 112.91 ms |
| P50 | 52.29 ms | 64.31 ms |
| P95 | 439.64 ms | 452.93 ms |
| P99 | 464.04 ms | 476.06 ms |
| 剩余库存 | 0 | 0 |
| 消耗库存 | 1000 | 1000 |
| 超卖检查 | 通过（`success <= stock`） | 通过（`success <= stock`） |
| 主要失败原因 | HTTP 429（网关限流） | 秒杀失败（库存售罄） |

## 4. 异步一致性验证

直连场景压测结束后补充观测（等待 45 秒）：

- `order_info` 最终订单数：`1000`
- Redis Stream 组信息：
  - `pending=0`
  - `lag=0`
- 流总长度 `XLEN=2760`（累计历史消息，不等同于当前积压）

结论：异步消费最终完成，数据达到最终一致。

## 5. 结果解读

1. 网关限流生效
   - 经网关场景大量返回 429，说明入口保护在工作。

2. 不超卖目标达成
   - 两个场景均满足库存扣减上界，未出现超卖。

3. 异步链路有效
   - 压测瞬时未全部入库属正常，经过消费窗口后订单数量与成功扣库存一致。

4. 口径注意事项
   - 若比较“系统承压上限”，建议看直连场景；
   - 若比较“生产防护效果”，建议看经网关场景（包含限流策略影响）。

## 6. 可用于论文的结论表述（可直接引用）

在 `3000` 请求、`300` 并发、`1000` 库存条件下，P1 方案在入口限流和异步落单机制下实现了“高并发可控 + 不超卖 + 最终一致”。经网关场景下系统通过 429 快速拒绝超配请求，保障后端稳定；直连场景下库存售罄后失败类型收敛为业务失败，且在消费窗口后订单落库与库存消耗一致，验证了 P1 方案的工程可用性。
