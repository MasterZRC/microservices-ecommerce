# 论文插图版：高并发秒杀实验一页表（2026-03-14）

## 实验设置（统一口径）

- 请求总量：`3000`
- 并发：`300`
- 初始库存：`1000`
- 商品：`productId=3`
- 压测脚本：`scripts/loadtest/p0-seckill-benchmark.mjs`
- 场景：
  - 对照组（无入口限流）：`http://localhost:8005`
  - 实验组（网关限流）：`http://localhost:8080`

## 核心结果表

| 指标 | 对照组：直连服务(8005) | 实验组：经网关(8080) | 结论 |
|---|---:|---:|---|
| 成功数 | 1000 | 537 | 网关限流下，成功请求数受入口阈值影响 |
| 失败数 | 2000 | 2463 | 失败从“库存售罄”转为“入口快速拒绝” |
| 主要失败原因 | 秒杀失败（库存售罄） | HTTP 429（限流） | 实验组具备保护后端能力 |
| RPS | 2412.49 | 2710.25 | 入口快速拒绝使总体响应吞吐更高 |
| P95 | 452.93 ms | 439.64 ms | 延迟同量级，实验组略优 |
| P99 | 476.06 ms | 464.04 ms | 尾延迟同量级，实验组略优 |
| 剩余库存 | 0 | 0 | 两组均售罄 |
| 超卖检查 | 通过 | 通过 | 两组均满足库存正确性 |

## 异步最终一致性验证（直连组）

- 压测后等待 `45s`：`order_info=1000`
- Redis Stream 消费组：`pending=0`、`lag=0`

结论：异步消费最终完成，订单落库与成功扣库存一致。

## 可直接放论文正文的总结句

实验表明，系统在高并发秒杀场景下可同时满足“库存正确性（不超卖）”与“工程稳定性（入口限流保护）”。与无入口限流对照组相比，经网关场景将大量超配请求以前置 429 的方式快速拦截，降低后端竞争压力；同时，异步订单链路在消费窗口后达到最终一致，证明方案具备生产可用性。
