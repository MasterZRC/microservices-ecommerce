---

## 一、目标

1. **理解项目**：梳理微服务边界、网关、数据与监控栈，形成可操作的架构认知。  
2. **完整启动**：`docker compose` 全栈跑通；处理构建/健康检查/依赖顺序问题。  
3. **全接口验证**：覆盖用户、商品、订单、推荐、秒杀、管理端、网关、排序服务等 REST 行为正确。  
4. **秒杀高并发**：多轮压测，校验库存一致、限流与异步下单链路。  
5. **推荐与模型**：ItemCF / 精排 / 灰度与特征链路可工作；容器内 MySQL 等配置正确。  
6. **可观测性**：Prometheus 抓取、规则加载、Grafana、Loki/Promtail、SkyWalking UI、告警闭环。  
7. **交付物**：接口清单与终验报告（见 `docs/final-report-2026-04-25.md`）。

## 二、阶段划分

### 阶段 0（只读）

- 阅读 `README.md`、`docker-compose`、各 `Controller` 与 OpenAPI 描述。  
- 产出**接口清单**（见 `docs/endpoint-catalog.md`）。

### 阶段 1：系统启动与健康

- 修复各 Java 服务 Dockerfile（SkyWalking Agent 包名/路径、curl 用于 healthcheck）。  
- 修复 `docker-compose` 中 Prometheus 规则目录挂载、SkyWalking UI 与 OAP 的 HTTP 端口等。  
- 确认 Nacos、MySQL、Redis、业务服务、网关、前端、监控组件状态。

### 阶段 2：全接口功能测试

- 按模块顺序调用并断言；修复业务异常被统一成 500、灰度接口误要登录、秒杀 `activity_id`、秒杀下单 `productId` 透传等问题。  
- 管理端 `LocalDateTime` 与 Redis 缓存序列化、告警 Webhook 路由等。

### 阶段 3：秒杀与推荐专项

- 使用 `scripts/loadtest/` 下 Node 压测脚本；必要时清理 Redis 测试键。  
- Python 精排服务：特征与模型对 `None` 的兼容、容器内 `MYSQL_HOST` 等环境变量。

### 阶段 4：监控与日志

- Prometheus 告警规则加载、Promtail 与 Docker API 版本、Loki 收日志。  
- 前端 401 与静态资源 404 等体验问题修复（不扩大范围）。
